# Spec: Supabase Data Layer

## Objective
Move the site's content from the static files in `public/data/*.json` into Supabase (Postgres), so the
Angular services can query Supabase instead of fetching `/data/*.json`.

**This spec covers the data layer only:** schema, security (RLS), seed data and generated types.
The Angular code that reads the data (services, `httpResource` calls in `tools.ts` and
`organizations.ts`, model changes) is **out of scope**. The developer writes that code.

Success: after `npx supabase db reset`, the local database contains every row from the 7 JSON files.
A browser client using the publishable (anon) key can read exactly the rows the site shows today and
cannot write anything.

## Tech Stack
- Supabase CLI `^3.1.0` (project devDependency, run with `npx supabase`; see `SUPABASE.md`)
- Postgres (the Supabase local stack in Docker)
- `@supabase/supabase-js ^2.119.0` (already installed; the developer uses it)

## Commands
```bash
npx supabase init                                   # once: creates supabase/
npx supabase start                                  # local stack (Docker Desktop)
npx supabase db reset                               # apply migrations + seed.sql locally
npx supabase gen types typescript --local > src/app/types/database.types.ts
npx supabase db push                                # remote, ONLY after approval
```

## Project Structure
```
supabase/
  config.toml                         → generated by `supabase init`
  migrations/
    <ts>_content_schema.sql           → 7 tables, constraints, indexes, updated_at trigger
    <ts>_content_rls.sql              → RLS enabled + public read policies
  seed.sql                            → data from public/data/*.json (generated once)
src/app/types/database.types.ts       → generated by the CLI, not hand-written
public/data/*.json                    → left untouched until the services are switched over
```

## Tables (source file → table)

Conventions: table and column names are `snake_case`. Every table gets `created_at` and `updated_at`
(`timestamptz`, default `now()`), and a trigger keeps `updated_at` current. The legacy fields
`created_by_id`, `created_by` (these contain personal emails) and `is_sample` are **not** migrated.
The JSON field `order` becomes `sort_order`, because `order` is a reserved word in SQL and in
PostgREST query strings.

| Table | Columns (type, constraint) |
|---|---|
| `events` | `id text pk`, `title text not null`, `description text`, `event_date date not null`, `event_time text`, `location text`, `event_type text check in ('Roundtable','Workshop','Hackathon','Conference','Webinar','Other')`, `registration_url text`, `is_upcoming boolean not null default false`, `url text` |
| `news` | `id text pk`, `title text not null`, `excerpt text not null`, `content text`, `image_url text`, `image_alt text`, `publish_date date not null`, `tags text[] not null default '{}'`, `is_archived boolean not null default false`, `is_published boolean not null default false` |
| `partners` | `id text pk`, `name text not null`, `acronym text not null`, `country text not null`, `logo_url text`, `website text`, `is_coordinator boolean not null default false`, `description text`, `sort_order int not null default 0` |
| `sister_projects` | `id text pk`, `name text not null`, `description text not null`, `website text`, `logo_url text`, `status text not null check in ('Onboard','Collaborator')`, `tags text[] not null default '{}'`, `contact_name text`, `contact_email text`, `is_featured boolean not null default false`, `featured_only boolean not null default false`, `is_coordinator boolean not null default false`, `belongs_to_project text`, `sort_order int not null default 0` |
| `resources` | `id text pk`, `title text not null`, `resource_type text not null check in ('Deliverable','Publication','Better Practice Guide','Policy Brief','Data & DMP')`, `description text`, `file_url text not null`, `publish_date date`, `authors text`, `work_package text`, `deliverable_number text`, `belongs_to_project text`, `is_published boolean not null default false`, `hide_publish_day boolean not null default false` |
| `tools` | `id text pk`, `title text not null`, `url text not null`, `description text`, `is_published boolean not null default false`, `sort_order int not null default 0` |
| `organizations` | `id text pk`, `name text not null`, `website text`, `description text`, `logo_url text`, `country text`, `is_published boolean not null default false`, `sort_order int not null default 0` |

- `id` stays `text`, and existing ids are kept as they are (`"69731c4a…"`, `"1"`), so URLs such as
  `/news/:id` keep working. New rows get `default gen_random_uuid()::text`.
- Indexes: on `sort_order` for the ordered tables, on `publish_date` for `news` and `resources`, and
  on `event_date` for `events`.

### Data cleanup done during the seed
- Dates are normalised to `YYYY-MM-DD`: `"2026-9-09"` → `2026-09-09`, `"09/09/2026"` → `2026-09-09`,
  and timestamps such as `2025-03-17T08:59:22.454000` → `2025-03-17`.
- Empty strings (`""`) in optional fields become `NULL`.
- `created_date`/`updated_date` are kept as `created_at`/`updated_at` where they are valid.
- JSON `belongsToProject` → `belongs_to_project`, and `isCoordinator` → `is_coordinator`.
- `resources.json` contained duplicate ids (`3` and `6` appear twice). Resources are therefore
  renumbered `1..32` in file order. No URL uses resource ids.

## Security (RLS)
- RLS is enabled on all 7 tables.
- `anon` and `authenticated` get **SELECT only**:
  - `news`: `is_published = true`. Archived items stay readable because the Archive page needs them.
  - `resources`, `tools`, `organizations`: `is_published = true`.
  - `events`, `partners`, `sister_projects`: all rows.
- No INSERT/UPDATE/DELETE policies. Content is edited from the Supabase Dashboard or with the
  service role, which bypasses RLS.

## Impact on the code you will write (for reference only)
- Model field renames: `order` → `sort_order`, `belongsToProject` → `belongs_to_project`, and
  `isCoordinator` → `is_coordinator`. `Event.id` becomes `string`.
- Unpublished rows no longer reach the client, so the `is_published` filters in the services become
  redundant. They are harmless if left in.
- `environment.supabaseUrl` is currently `http://localhost:3000/api`. The local Supabase API runs at
  `http://127.0.0.1:54321` (see `npx supabase status`).

## Testing Strategy
Run these checks against the local stack after `db reset`:
1. Row counts match the JSON files: events 6, news 10, partners 10, resources 32, sister_projects 9,
   tools 3, organizations 3.
2. An anon REST call (`curl` with the publishable key) on `tools` and `organizations` returns 2 rows
   each, because the unpublished ones are hidden.
3. An anon `POST`/`PATCH`/`DELETE` is rejected.
4. `gen types` runs without errors, and `npm run build` still passes (no code changes).

## Boundaries
- **Always:** keep all schema changes in `supabase/migrations/` (never edit the database by hand);
  keep `seed.sql` reproducible; run `db reset` before declaring done.
- **Ask first:** `db push` / `link` to the remote project; changing an existing column or id; adding
  Storage buckets.
- **Never:** touch `src/app/services/*`, components or models; commit secrets or the service-role key;
  delete `public/data/*.json`.
